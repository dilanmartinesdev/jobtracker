# Audit log

How the project was reviewed, what was found, and how each finding was fixed. Where a fix has an automated test, its name is listed so it can be found. Round 2 findings 16–19 (CSP fonts, proxy headers, accessibility) were found and re-checked in a real browser or with axe-core and have no automated test in the repository yet; that is stated rather than implied. Round 2 finding 14 is covered by `Card.test.tsx`, and 15 by the backend test named in its row.

Tools used: Ruff (with security and bug-pattern rules), mypy `--strict`, Bandit, pip-audit and `npm audit`, pytest with coverage on SQLite and PostgreSQL, Vitest, axe-core, and a real browser driven with Playwright against a real PostgreSQL database.

## Round 1: the first version of the API

The first version passed its own tests. These problems were found by writing probes that tried to break it and reading the results.

| # | Finding | Evidence | Fix | Test |
|---|---|---|---|---|
| 1 | Password over 72 bytes crashed registration with a `500` | 40 emoji (160 bytes) → server error (bcrypt limit) | Argon2id; length limit by characters | `test_multibyte_password_does_not_crash` |
| 2 | `PATCH {"company": null}` crashed with a `500` | `NOT NULL` violation reached the database | Validator rejects `null` for required fields (`422`) | `test_patch_cannot_null_required_fields` |
| 3 | `javascript:` URLs were stored | Accepted and returned as `url` | `http(s)`-only validation | `test_create_rejects_invalid_input` |
| 4 | A 2 MB note was accepted | `201` for a 2,000,000-character body | 5,000-character limit | `test_create_rejects_invalid_input` |
| 5 | Registered emails could be discovered by timing | Unknown email ≈ 7 ms, known email ≈ 290 ms | Verify against a dummy hash when the user does not exist | `test_unknown_user_still_pays_the_hashing_cost` |
| 6 | Interview rate ignored applications that moved on | Interview → Rejected removed it from the rate | Status history table; funnel counts "ever reached" | `test_stats_count_stages_reached_not_just_current_column` |
| 7 | `?q=%` matched every row | LIKE wildcards were not escaped | `icontains(..., autoescape=True)` | `test_search_treats_percent_and_underscore_literally` |
| 8 | Timestamps had no timezone | `created_at` came back naive | `UTCDateTime` type | `test_timestamps_are_timezone_aware_utc` |
| 9 | Unlimited login attempts | 25 wrong passwords in a row, all answered | Per-client rate limit | `test_login_is_rate_limited` |
| 10 | Tokens could be forged | The default `SECRET_KEY` was in the repository | No default: random in development, required in production | `test_token_signed_with_another_key_is_rejected`, `test_production_refuses_to_start_without_a_strong_secret` |
| 11 | CORS allowed credentials and every method and header | Configuration review | Only the methods and headers in use; no credentials (the token is a header) | `test_cors_allows_only_configured_origins` |

Also added in this round: pagination with a total, a readiness endpoint that checks the database, constraint names for migrations, foreign keys enforced on SQLite, account deletion with cascade, and typed settings.

## Round 2: running the whole system

Problems that only appeared when everything ran together in a browser or under production-like settings.

| # | Finding | How it was found | Fix |
|---|---|---|---|
| 12 | The list route crashed the app on import | Test run: the return annotation `Page[Application]` (a database model) made Pydantic build an invalid schema | Return the output schema; build it explicitly |
| 13 | The autogenerated migration imported an application type | Reading the generated file | Rewrote it self-contained; `alembic check` in CI guards drift |
| 14 | Pressing Enter on a card opened the dialog and closed it at once | Keyboard test in the browser: focus moves to the dialog's Close button, and the same Enter press then activated it | `preventDefault()` on Enter (`Card.test.tsx`; removing the line makes it fail) |
| 15 | An accidental drag followed by Undo permanently raised the interview count | Screenshot review: stats read 9 instead of 8 after an undone move | Reversing the last move within 2 minutes erases it (`test_quick_undo_erases_the_move_instead_of_inflating_the_funnel`) |
| 16 | The CSP blocked fonts | Loading the production build with the real headers: Vite had inlined small fonts as `data:` URIs | `assetsInlineLimit: 0`; re-verified with zero violations |
| 17 | Behind nginx, every request would look like it came from one address | Reviewing the deployment: the rate limiter would share a single bucket across all users | nginx overwrites `X-Forwarded-For`; the API trusts it only inside the compose network. Verified: 10 attempts from one address are limited, 12 from different addresses are not |
| 18 | Cards' accessible names did not include their visible text (WCAG 2.5.3) | axe-core | Removed the custom `aria-label`; the name comes from the content |
| 19 | The board page had no `h1` | axe-core | The app name is the page's `h1` |

After the fixes, axe-core reports **0 violations** on sign-in, sign-up, the board and both dialogs, in light and dark themes, on desktop and phone widths.

## Checking that the tests are real

A test that cannot fail proves nothing. As a spot check, the optimistic rollback was removed on purpose; the test "puts the card back when the server refuses" failed, and passed again once the code was restored.

## Round 3: independent review

Two reviewers who had not seen the work being produced read the finished code: one for correctness and security, one as a hiring manager looking at the repository for the first time. Their findings and what was done about them follow.

### What the hiring-manager review said

The reviewer opened the repository cold, as a technical recruiter and engineering manager would, and judged it a "maybe, leaning yes" for a junior role. Strengths named: the project is coherent end to end, the documentation states trade-offs and limits, and the audit is verifiable. Weaknesses named, and what changed:

| Finding | Action |
|---|---|
| The README claimed CI enforces accessibility, but axe-core is not in CI | Reworded in both READMEs: accessibility and browser flows were checked by hand and the scripts are on the roadmap |
| The Docker job had never run | README says so explicitly |
| The board fetched at most 500 rows and dropped the rest without saying so | `fetchAllApplications` follows the pages until `total`; three tests cover one page, several pages and a wrong total |
| Sign-up answers `409` for an existing email, which reveals registered addresses | Kept on purpose and documented under known limitations and in [decisions](decisions.md); login does not leak |
| "Each fix has a test" was stronger than the facts | Rewritten above to say which findings have automated tests and which do not; finding 14 now has one |
| Demo data was too rosy (10 of 18 reached an interview, 3 offers) | Now 6 of 18 reached an interview and one offer; a test checks that every seeded status matches its history |
| A placeholder was left in this file | Replaced by this section |

Not done, and why: splitting `ApplicationDialog`, component tests for the dialog and board, a frontend coverage gate and Prettier are real improvements but were judged smaller than the items above. They are the next steps.

### What the security review covered

The correctness and security reviewer was stopped by a platform rate limit before reporting, so there is **no independent security review of this code**. The checks listed at the top (Ruff security rules, Bandit, pip-audit, `npm audit`, the probes of Round 1 and the CSP and proxy tests of Round 2) are what exists. Someone reading the code for authorization mistakes would still add value.


## What this audit did not cover

- **Docker.** Docker was not available in the environment where this was built. The Dockerfiles, compose file and nginx configuration were written carefully and the CSP and proxy behaviour were verified by other means, but the CI `docker` job is the first real build of the images.
- **Python 3.12.** The code was tested locally on Python 3.13; CI uses 3.12. It uses nothing newer than 3.12.
- **Load and penetration testing.** Not performed.
- **Real deployment.** There is no hosted instance yet.
